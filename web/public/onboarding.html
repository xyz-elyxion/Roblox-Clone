Onboarding

Get to know the whole build

Nine short steps through everything this project ships: the website, the client and the game servers, Studio, RBLXCode and the trainer. The steps the site can verify check themselves; the rest you tick off as you do them. Progress is remembered in this browser.

A · Setup

  1. 1 Start the website WebApp.exe serves this very page Checking

    You are already here, so this one is done. WebApp.exe is the website: pages, accounts, avatars, published games, and the launch button that starts a game server.

    It opens a console window with the live log, every running game server and that server's output. The default address is http://localhost:3000; set PORT to change it. Closing the console stops the site and its servers.

    Contacting the website…

  2. 2 Make an account One login for the site, the client and Studio Checking

    Accounts live in web/users.json. The website signs you in with it, the client uses the same token to join a game, and Studio uses it to publish. Nothing is sent anywhere else: this is a local build.

    Signing up solves a captcha, which is what keeps the automated-cheat reporting honest and proves a real person is creating the account.

    Checking for a session…

    Sign up Log in
  3. 3 Change your avatar Faces and hats travel to the client and the server Checking

    The avatar is stored on the account, so it follows you into every game: the server sends the face and hat to the other players, and the client draws the same character. Coins come from playtime, and the shop spends them.

    Checking your avatar…

    Open avatar

B · Play

  1. 4 Join a game Play starts Server.exe and Client.exe for you Checking

    Open a game page and press Play. The website starts a Server.exe for that world on its own port, then launches Client.exe. The console window lists that server with its port, players and output, and the client's Play button is the same page.

    If Play fails, the reason is in web/game-server-logs/. Playtime is reported back to the site every minute, which is how this step checks itself.

    Checking for recorded playtime…

    Browse games
  2. 5 Add someone Friends, requests and presence Checking

    The dashboard has friends, requests and a user search. Presence is live while a browser tab is open, and the search is also how you find someone's profile.

    This is the one step that needs a second account: sign up in a private window, then send a request between the two.

    Checking for friends…

    Find people

C · Create

  1. 6 Open Studio The world editor: parts, scripts, lighting To do

    Studio.exe opens the world editor. It works on ServerWorld.world and on the example worlds in games/, and its script panel highlights the project's own .rbx language.

    A world is a text file, so everything you build in Studio is diff-able and editable by hand.

    Open Studio from the package folder and save a world.

  2. 7 Publish a world Your games, your account, your page Checking

    Publish from Studio's publish dialog or from the website's Create page. The site checks the world before accepting it, then gives it a page you can play from like any other game.

    Checking your published games…

    Publish a world

D · Extend

  1. 8 Edit the project in RBLXCode The editor built for this repository To do

    RBLXCode.exe opens the folder it is in, so shaders/, web/public/ and games/ are all editable. Point it at a source clone to edit the C++ as well.

    Its shortcuts are the ones you would expect: Ctrl+P opens a file by name, Ctrl+F finds and replaces, Ctrl+G goes to a line, Ctrl+S saves with the line endings the file already had. It also has an outline panel, Ctrl+Tab cycle, Alt+Left/Right history and reloads a file that changed on disk.

    Open RBLXCode, edit a script and save it.

  2. 9 Train a bot AiTrainer.exe learns a route, headless To do

    AiTrainer.exe drives the same character and physics the game uses, without a window or a GPU. It learns a policy for one world and writes it to models\<world>.policy, then replays it.

    Run the trainer from the package folder against one of the example worlds.

That is the whole build

Nine steps done. The site, the client, the game servers, Studio, RBLXCode and the trainer are all in the same repository, and each one is a small program you can read and change.
