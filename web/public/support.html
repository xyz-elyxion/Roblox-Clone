Help

Support

Last updated 13 November 2026

RBLX Clone is a self-hosted prototype, so there is no support desk behind it: the person who runs the install is the person who can read the data file, the server log and the game-server logs. This page collects the problems people actually hit in this build and what fixes each one, so most of them do not need anybody else.

The site loads but every list is empty

Every page is plain HTML served by WebApp.exe, and everything on the page is fetched from it. If the pages open but games, friends or chat stay empty, or a banner says the site cannot be reached, the backend is not running or is on another port. Start WebApp.exe from the folder the site was installed to and reload; the port it prints on start is the one to open.

Signing in

  • The session is a signed token kept in this browser's localStorage. It expires after the lifetime the operator configured, seven days by default, and an Invalid or expired token answer means exactly that: sign in again.
  • Logout removes the token from this browser. Signing out on one browser does not sign out another one.
  • Forgotten password. When the account was created the site showed a recovery code once. Sign in has a recovery form below the password box: the username plus that code sets a new password. A new code can be generated from Settings while you are still signed in, and generating one replaces the old code.
  • If the password and the recovery code are both gone, nobody can recover the account: the site keeps only hashes, so there is nothing to read back. The operator can remove the account, and a new one starts from nothing.

Chat

  • Reading a room is open to anyone. Posting needs an account and an account that is not suspended or banned; Settings shows the standing and any infractions.
  • A message may be 500 characters. One account may post five messages in ten seconds, and the composer shows the wait the server sent back rather than losing the text.
  • A private game's room answers 404 to everyone but its owner.
  • Blocking an account hides both sides' messages from each other, and the log says how many it hid instead of looking truncated.

Files, voice clips and the scanner

  • One attachment per message, up to 2 MiB. Allowed files are PNG, JPEG, WebP and GIF pictures, WebM, Ogg, WAV, MP3 and M4A audio, and TXT, MD, LOG, WORLD and RBX text. Anything else, including installers, archives and web pages, is refused by name.
  • Every file is scanned before it is stored. A clean file is posted normally. A file the scanner doubted is kept but labelled, and it is served as a download rather than drawn. A blocked file is refused with the name the scanner gave it, for example Win32.Executable, Trojan.Downloader or Trojan.Macro; that gate is a fixed set of checks, not an anti-virus, so a file it accepts is not a promise that the file is safe.
  • Voice records a clip of up to sixty seconds and posts it as a message. It is not a live call, and this build cannot make one.
  • If recording does nothing, the browser refused the microphone. The site asks for permission the first time; the answer lives in the browser's site settings, not in this account.

A game will not start

Play on a game page asks the backend to start a local game server and hands the client what it needs to join. A failure is almost always one of three things: the game has no world file, the game is private and not yours, or the server could not be started. The console of WebApp.exe lists each running instance, and every instance writes its output to web/game-server-logs; the admin dashboard shows the same list to an administrator.

Moderation, appeals and reports

  • Settings shows the account's standing, its infractions, and a form to appeal one. An appeal is read by the people with the appeals permission, and the answer appears in the same panel.
  • Report on a game's page files a report against that game, with a reason, which the admin dashboard lists newest first. A block is for your own account; a report is for the operator.
  • A ban reaches the account in a wave: the next authenticated request after the wave is answered with it, and a banned account can still read the site.

Your data

Settings can download everything kept about the account as JSON — profile, avatar, playtime, coins, friends, blocks, the games you own, the chat messages you posted and the files attached to them with their scan verdicts — and can delete the account after asking for its password. The install owner cannot be deleted, because the install cannot be recovered without it. Privacy describes what is stored and where it lives.

Who to ask

Ask the person who runs this install: they started WebApp.exe, they have the data file and the logs, and this build has no external support address to write to. If you are the operator, the tour covers the setup, the developer page covers tokens for the trainer, and the project's README.md and HOSTING.md next to the executables cover the rest. Problems that look like a bug in the build are worth writing down with the page, what you clicked and what the console printed, so the next person can reproduce them.
