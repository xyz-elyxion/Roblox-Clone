Last updated 1 November 2026

RBLX Clone is a self-hosted prototype: the website, the game server and the player all run on one machine that you or someone you know controls. This page explains what that install keeps and who can see it. It describes what this build actually does, not what a commercial service would do.

What the site stores

  • Account. Username, numeric user id, and a password hash. Passwords are stored as PBKDF2-SHA256 hashes with a random per-account salt, never as plain text, and the site cannot show you your password because it does not keep it.
  • Recovery code. The one-time code shown when the account was created is kept only as the same kind of PBKDF2-SHA256 hash, so it cannot be displayed again; a new code replaces the old one when you generate one or use one to reset a forgotten password.
  • Activity. The time of your last signed-in request, used to show friends an online dot. It is never shown on a public profile.
  • Safety choices. The accounts you blocked and the reports you filed. A report carries your username so an admin can follow it up, and its target and reason.
  • Session. When you sign in the site issues a signed token (a JSON Web Token) that your browser keeps in localStorage. It holds your user id and username and expires after the lifetime the operator configured, seven days by default.
  • Profile and avatar. Body colours, face choice, hats you own or wear, coin balance, playtime seconds, and your friends and friend requests.
  • Games you publish. Title, description, public or private flag, the world file and any script that belongs to it, and who created it.
  • Server output. The web server log and, for each game instance it starts, a log file containing that game server's console output.

Where it is kept

Everything lives on the machine running the site: accounts in a JSON data file (web/users.json by default), published worlds under web/game-worlds, and game-server logs under web/game-server-logs. The operator of the install can read, copy or delete those files at any time. Nothing is sent to a third-party analytics, advertising or tracking service, and this build does not use cookies at all.

What other people can see

  • Your username, user id, avatar, playtime and friend count are visible to anyone who opens your profile or searches for you.
  • Games you publish as public are listed on the games page with your name as the creator.
  • Players in the same game instance see your character, its colours and face, and your chat messages. Hats are not sent to other players in this build.
  • Your password hash, session token and coin balance are never shown to another account. The admin dashboard does show an admin the user list, game list and running servers.

What the browser remembers

Besides the session token, the site stores your username, your user id, and the Reduce motion preference from Settings in localStorage. They stay there until you log out or clear site data for this address. Logging out removes the token and the cached username and id; the display preference stays.

Retention, export and deleting your data

Account data is kept until you or the operator removes it. The Settings page can download everything kept about the account as JSON — profile, avatar, playtime, coins, friends, blocks and the games you own, without the password or recovery hashes — and can delete the account after asking for its password.

Deleting an account removes its profile, avatar, playtime, coins, friendships, blocks and the reports it filed, together with its games, their published world files and any game server running for them. Deleting a single game from its page or the admin dashboard is immediate in the same way. One account cannot be deleted: the install owner, which is the account created when the site was first started, because the install cannot be recovered without it. Ask the operator if that account has to go.

Children

The site is a local prototype, not a service aimed at children, and it does not verify anyone's age. It has no parental controls or consent flow. If you are not old enough to agree to these terms where you live, do not create an account.

Security

Passwords are hashed with PBKDF2-SHA256 and sessions are signed tokens, but this is a prototype: the backend serves plain http:// with no TLS, keeps its data in a JSON file, and has not had a security review. Treat it as something to run on your own machine or local network, not as a place to store a password you use anywhere else.

Changes

This page changes when the stored data changes. The date at the top is the last time it was updated, and the operator of an install is responsible for keeping it accurate for that install.

Contact

Questions about data on this site go to the person who runs it — the same person who starts WebApp.exe and can see its files. See also the Terms and Conditions.
